# 4단계: 공개 명함 화면과 관리자 화면

현재 상태는 **로컬 구현 및 데모 검증 완료, Google 공개 프로젝트 파일 반영, 인증·배포 미확인**입니다. 기존 개인 계정의 Form 자동화는 최신 저장소 코드로 갱신하지 않았습니다. 따라서 운영 4단계 전체가 완료된 상태는 아닙니다. 전체 후속 작업과 최종 Cafe24 배포 순서는 [통합 체크리스트](release-roadmap.md)를 따릅니다.

## 구현한 기능

- 원본 `cardDesign/명함_디자인/index.html`의 CSS·카드 배치·인트로·전환 동작을 사용합니다. 직원 이름, 한국어·영문 직함과 직무 5개, 연락처, 회사 로고·슬로건·주소를 연결했습니다. 프로필은 이미지이고 나머지 네 배경은 DEFAULT/IMAGE/VIDEO를 구분합니다.
- 공개 조회는 활성·공개 명함만 반환합니다. Google 계정 이메일, 내부 UUID, 오류 내용은 공개 응답에 넣지 않습니다. 영상 요청도 명함 상태를 검사하고 서버가 해당 영역의 파일 ID를 결정합니다.
- QR와 공유는 Sheet에 저장된 고정 `publicUrl`을 사용합니다. Google Apps Script 내부 iframe 주소를 사용하지 않습니다. QR은 포함된 오픈 소스 라이브러리로 브라우저에서 생성합니다.
- 간략 명함 디자인에 맞춘 626×1110 PNG를 브라우저에서 생성·다운로드합니다. 프로필 사진·영상·버튼을 넣지 않고 Drive 저장본을 만들지 않습니다. 긴 텍스트는 영역 폭에 맞춰 글자 크기를 줄입니다.
- Sheet 메뉴의 **명함 관리**에서 목록, 이름·부서·직함·이메일 검색, 상태 필터, 공개·비공개·처리 중·오류 통계를 표시합니다.
- 관리자 정보 수정, 회사 공통정보 수정, 실제 공개 템플릿을 쓰는 미리보기, URL 열기·복사, 배경 기본값 복원 기능을 제공합니다. 미디어 교체는 현재 Drive 파일 ID를 입력하는 방식이며 파일 선택 UI는 아직 없습니다.
- 비활성화하면 비공개로 바뀌고 설문 수정이 차단됩니다. 재활성화 후 공개 여부는 별도로 지정합니다. 오래된 편집본과 처리 중인 명함은 저장하지 않습니다.
- 처음 공개 기본 주소를 설정할 때 기존 명함의 빈 주소만 채웁니다. 이미 발급된 주소가 있으면 기본 주소 변경을 거부합니다.
- Form 재제출에서 `KEEP_CURRENT` 처리용 값이 저장되지 않도록 수정하고, 수식으로 해석될 수 있는 Form 텍스트를 이스케이프했습니다.

## 빌드 및 로컬 검증

```sh
npm ci
npm run build
npm test
npm run demo
```

데모는 `http://127.0.0.1:4173`에서 실행됩니다. 저장소 예시 이미지와 원본 영상을 쓰며 운영 Sheet를 읽거나 변경하지 않습니다. 데모 회사 주소·전화는 검증용 예시입니다.

`scripts/build-web.cjs`가 공개 Card.html, 관리자 Preview.html, PreviewData.gs를 생성합니다. 생성물을 직접 수정하지 말고 `web/card-service.js`, 공개 Code.gs, 원본 디자인을 수정한 뒤 빌드합니다. 공개와 관리자 미리보기는 같은 HTML을 사용하되 호출하는 RPC가 다릅니다.

Edge에서 실제 텍스트 표시, 기본 영상 배경, QR 표시, PNG 다운로드를 확인했습니다. 내려받은 PNG는 626×1110입니다. Google 서비스는 Node 테스트에서 대역을 사용하므로 실제 권한·웹 앱 RPC·모바일 환경의 검증을 대신하지 않습니다.

## 운영 연결에 남은 작업

1. Form·Sheet ID의 하드코딩을 제거했습니다. 계정별 Script Properties의 `ZNUS_FORM_ID`, `ZNUS_SPREADSHEET_ID`가 필수이며, 누락되면 중단합니다. 운영 Sheet에 바인드된 프로젝트에서 `connectExistingForm(formId)`를 호출하면 기존 연결, 설문의 응답 저장 위치, 이메일 수집 여부를 확인하고 속성을 저장합니다. 질문·제출 트리거는 변경하지 않습니다. `inspectFormConnection()`으로 현재 계정·프로젝트의 트리거를 확인한 뒤, 이전 단일 프로젝트의 트리거도 확인하고 이전해야 합니다.
2. `apps-script/admin-bound` 파일들을 운영 Sheet의 바인드 프로젝트에 반영합니다. 관리자 프로젝트는 공개 웹 앱으로 배포하지 않습니다. 현재 코드는 Sheet 편집자가 자기 권한으로 관리 대화상자를 여는 구조입니다.
3. 원본 assets의 `role.mp4`, `contact.mp4`, `web.mp4`, `links.mp4`, `universe.jpg`, SVG 로고를 HTTPS 정적 주소에서 제공하고 두 프로젝트의 `ZNUS_ASSET_BASE_URL`에 assets 폴더 주소를 설정해야 합니다. 필수 프로필은 업로드 이미지이므로 63MB의 원본 profile.mp4는 필요하지 않습니다. 정적 영상 주소는 아직 배포되지 않았습니다.
4. 별도 공개 프로젝트에는 **public-web 폴더만** 반영하고 manifest의 읽기 전용 권한을 사용합니다. `ZNUS_SPREADSHEET_ID`를 실제 운영 Sheet ID로 설정합니다. 웹 앱 실행 주체와 익명 접근을 설정한 후 배포·인증합니다.
5. 발급된 `/exec` 주소를 관리자 `saveAdminPublicBaseUrl(url)`에 전달합니다. 기존 데모 명함의 토큰은 유지하고 빈 URL만 채웁니다. 이미 발급된 URL은 변경하지 않습니다.
6. 실제 업로드 이미지·5초 MP4, 기본 영상, 비공개 차단, 수정 차단, Google iframe 안의 PNG 저장과 회사 로고 로딩을 모바일/PC에서 검증합니다. 업로드 영상은 토큰 검증 후 RPC로 전체 데이터를 받아 Blob URL로 재생하므로 초기 로딩 및 메모리 사용을 확인해야 합니다. 자동 포스터 추출은 구현하지 않았으며 기본 이미지로 대체합니다.

## 후속 운영 기능

완전 삭제(원본 Form 응답·응답 시트·자산의 영구 삭제와 실패 재시도), Drive 파일 선택 UI, 관리자 QR 다운로드, Cafe24/사용자 도메인 배포는 미완료입니다. 현재 대시보드에는 완전 삭제 버튼을 노출하지 않습니다. `DeletedTokens`의 토큰 재사용 금지 규칙은 유지합니다.

## 2026-09-10 운영 연결 시도

Edge에서 개인 계정의 운영 Sheet를 확인했습니다. `확장 프로그램 → Apps Script` 클릭은 자동 승인 검토의 사용량 한도 초과로 거절되었습니다. 안내된 재시도 시각은 오후 8시 2분이며, 이 시도에서 Google 프로젝트·시트·Form 데이터는 변경하지 않았습니다. 로컬 연결 설정 개선만 반영했고 테스트 31개를 통과했습니다.

### 공개 프로젝트 준비 및 권한 승인 기록

- 후속 재시도에서는 브라우저 조작이 가능해졌습니다. 기존 Form 자동화 프로젝트는 직접 URL로 열렸고, 운영 Sheet와 Drive 폴더 속성을 확인했습니다. 기존 자동화 코드·트리거는 변경하지 않았습니다. Sheet 메뉴에서 여는 바인드 프로젝트 주소는 여전히 Google 오류 페이지로 연결됩니다.
- 개인 계정 `phj3137@gmail.com`에 `ZNUS 공개 명함 (개인 테스트)` 프로젝트를 생성했습니다. 프로젝트 ID는 `1Kzshw1mU_In357xUnRCf2EOqGTjbHhsGGFpnAQPrS3onBaMYwefwl-YO`입니다. 재개할 때 새 프로젝트를 만들지 말고 이 프로젝트를 사용합니다.
- Code.gs와 Card.html을 각각 저장했고 `ZNUS_SPREADSHEET_ID`를 개인 운영 Sheet ID로 저장했습니다. 처음 시도한 큰 단일 문자열 입력은 편집기 응답 지연으로 실패했으나, 새 탭에서 분리 파일을 붙여넣어 복구했습니다.
- `appsscript.json`에 저장소의 읽기 전용 manifest를 입력했지만, 저장 버튼은 자동 승인 검토에서 거절된 이력이 있습니다. 이후 사용자가 개인 계정의 Sheets·Drive 읽기 권한과 익명 공개 배포를 명시적으로 승인했습니다. **권한 승인은 확보됐지만 manifest 저장 완료·인증·공개 배포는 아직 확인되지 않았습니다.** 최종 Cafe24 운영 배포는 검증 결과를 확인한 뒤 진행합니다.
- 권한 범위는 Google OAuth의 Sheets 및 Drive 읽기 권한입니다. 공개 RPC는 서버에서 활성·공개 명함만 반환하고 임의 파일 ID 요청을 받지 않습니다. 승인 후 실제 배포 및 익명 조회를 검증해야 합니다.
- `scripts/deployment-review.cjs`는 공개 프로젝트의 `/code`, `/card`, `/manifest` 세 소스만 localhost:4174에서 텍스트로 제공합니다. 관리자 파일이나 임의 로컬 경로는 노출하지 않습니다.
- 기본 영상의 GitHub 커밋 기반 jsDelivr 주소는 404로 확인됐습니다. 기본 영상의 제공 주소와 완전 삭제 기능은 여전히 미완료입니다.
